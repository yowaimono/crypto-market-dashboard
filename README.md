# crypto-market-dashboard

加密货币大盘：全市场异动扫描 + K 线 + 多周期动量 / 波动率看板。

## 运行
```
cd crypto-market-dashboard
node server.js
```
浏览器打开 http://127.0.0.1:8787

零 npm 依赖（Node 18+ 内置 fetch 即可）。环境变量：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `PORT` | 8787 | 监听端口 |
| `HOST` | 127.0.0.1 | 监听地址 |
| `MIN_QUOTE_VOLUME` | 300000 | 扫描的 24h 成交额下限（美元），调低能扫到更小的币 |

## 为什么需要后端
1. **CORS / 地域封锁**：浏览器直连交易所会被拦，Binance 现货 API 在部分网络直接 451；
   这里改用不受封锁的 `data-api.binance.vision`，统一由后端代理。
2. **全市场扫描**：要发现“现在谁在疯涨”必须扫几百个交易对（每次 100 根 5m K 线），
   这活儿只能后端干，结果缓存后再给前端。
3. **限频与算力**：扫描结果缓存 90 秒并做 stale-while-revalidate，请求永远秒回。

## 核心：全市场异动扫描（不预设币种）
不再写死币种列表，改为每轮动态发现：

1. 一次 `/ticker/24hr` 拉全市场（约 3700 个交易对）；
2. 过滤出 USDT 现货对，剔除稳定币 / 封装资产（WBTC、STETH…）/ 杠杆代币（`UP``DOWN``BULL``BEAR`）；
3. 保留 24h 成交额 ≥ `MIN_QUOTE_VOLUME` 的（默认约 386 个）；
4. 并发 16 拉每个交易对的 5m K 线 100 根（weight 1），算 5m / 15m / 30m / 1h / 4h 动量、1h 波动率、量能倍数。

**扫描发现的异动币会自动并入「动量与波动率」热力图**（表内用蓝点标记），
也会进入 K 线币种下拉框；点击扫描表任意一行即可直接看它的 K 线。

## 接口
| 接口 | 说明 |
| --- | --- |
| `GET /api/scan` | 全市场扫描结果：386 个交易对的 5m/15m/30m/1h/4h 动量 + 波动率 + 量能 |
| `GET /api/market` | 大盘总览（总市值/成交额/BTC·ETH 主导率）+ 恐惧贪婪 31 天序列 + 前 30 币行情 |
| `GET /api/momentum` | 观察名单 + 扫描异动币的多周期动量 / 波动率 + 市场宽度 |
| `GET /api/klines?symbol=MDXUSDT&interval=5m&limit=240` | OHLCV，周期 `5m/15m/30m/1h/4h/12h/1d` |
| `GET /api/health` | 可选币种（观察名单 + 扫描异动币）与周期 |

## 指标口径
- **动量 `m5/m15/m30/h1/h4`**：最新收盘 ÷ N 根前收盘 − 1，N = 1/3/6/12/48（5m K 线）
- **`rets.5m … rets.24h`**（/api/momentum）：N = 1/3/6/12/48/144/288
- **已实现波动率**：5m 对数收益标准差 × √288（一天 288 根 5m）→ 日均波动率 %
  - `rv1h` 近 1 小时、`rv4h` 近 4 小时、`rv24h` 近 24 小时
- **波动扩张 `volExpansion = rv1h / rv24h`**：>1 波动放大
- **量能 `acc = 近1小时成交额 / (24h成交额/24)`**：>1 放量
- **市场宽度 `breadth`**：各周期上涨币种占比

> 扫描里的 `c24` 与成交额直接取自交易所 24h ticker，其余指标由 5m K 线算出。

## 页面结构
1. 大盘指标块 + 情绪徽标
2. **K 线**：20+ 币种 × 7 周期，canvas 手绘蜡烛 + 成交量 + 十字光标
3. **全市场异动扫描**：按 5m/15m/30m/1h/4h 排序切换、币种搜索、点击行看 K 线
4. **动量与波动率**：结论、热力图（含扫描异动币）、波动率排行、动量×波动率四象限
5. 恐惧贪婪曲线、市值占比环图、市值前十

## 主题（浅色 / 深色）
默认跟随系统（`prefers-color-scheme`），头部可切 **浅色 / 深色 / 跟随系统**，选择存在 `localStorage.cmd-theme`；
也支持 `?theme=dark` / `?theme=light` 临时指定（不落盘，便于截图与调试）。

整套配色都由 CSS `light-dark()` 定义，所以切换只需钉住 `color-scheme`（`html[data-theme]`），无需维护两份色板。
但 canvas 与 Chart.js 读不到 CSS 变量，其颜色由 JS 探测后缓存，**换主题必须重算并重绘**（`refreshThemeColors()`），
否则 K 线、热力图、散点会停留在旧主题的颜色上。

顶部标签可切 **大盘行情 / Hyperliquid**，也支持 `?view=hyperliquid` 直接进入。
板块结构对齐 <https://www.coinglass.com/zh/hyperliquid>：

| 板块 | 内容 |
| --- | --- |
| 鲸鱼持仓总览 | 仓位 / 保证金 / 盈亏 / 资金费，各自带多空拆分与占比 |
| 大户持仓 | 前 50：用户 / 资产 / 方向+杠杆 / 仓位 / 未实现盈亏(%) / 开仓价格 / 爆仓价格 / 保证金 / 资金费 / 价格 / 开仓时间 |
| 最新鲸鱼动态 | 最近 50 笔：地址 / 资产 / 操作 / 仓位 / 价格 / 时间 |
| 持仓人数多空比 | 多空人数与比值 + 近 7 天曲线 + 178 个币种的多空占比 |

### 数据来源与口径
全部来自 **CoinGlass**（`capi.coinglass.com`），客户端实现在 `lib/coinglass.js`（零依赖），
协议是 **双层 AES-128-ECB + gzip**，逆向过程见 `D:/WorkSpace/coinclass-re`。
Key0 按响应头 `v` 派生：v=0 用 `cache-ts-v2`，v=1 用 URL path，v=2 用 `time` 响应头。

三个对齐页面时踩到的口径细节：

1. **总览是聚合出来的**：把 `topPosition` 全量按 `size` 正负分组求和得到，不是单独接口。
2. **资金费要反号**：原始 `fundingFee` 与页面显示符号相反（页面多单资金费为负），展示时取 `-fundingFee`。
3. **鲸鱼动作要两步判定**：`state` 1=开仓 / 2=平仓，再结合 `size` 正负才能得出
   买入开多 / 卖出开空 / 卖出平多 / 买入平空。

> 接口为非官方逆向，随时可能失效。四路数据用 `Promise.allSettled` 并行取，失败原因写进响应的 `errors` 字段。
> CoinGlass 数据版权归其所有，仅供个人看盘，缓存 20 秒。

## 策略模拟盘（第三个标签页）
顶部标签可切 **大盘行情 / Hyperliquid / 策略模拟盘**，也支持 `?view=strategy`。

在页面里直接写策略、跑回测，**全部在浏览器本地执行，不占后端**。

### 策略写法
编辑器里写的是函数体，`return` 目标方向：**1 做多 / -1 做空 / 0 空仓**。

可用函数：`MA(n)` `EMA(n)` `RSI(n)` `ATR(n)` `MACD(f,s,g)` `BOLL(n,k)` `crossover(a,b)` `crossunder(a,b)` `highest(n)` `lowest(n)` `price` `volume` `POS`。
序列取值：`.v` 当前根、`.p` 前一根、`.at(k)` 前 k 根；`POS` 当前仓位、`ENTRY` 开仓价、`BARS` 已持仓根数（写止损止盈要用）。

### 回测口径
- 信号在**当根收盘价**成交；开仓名义价值 = **当前权益 × 杠杆 × 仓位比例**（复利）
- **仓位比例** 1%~100%，默认 100%（全仓）。比例越小单笔风险越小：爆仓只亏掉该笔保证金（= 名义 ÷ 杠杆），
  只有权益跌破初始的 1% 才判定「出局」并停止；100% 仓位下一次爆仓即归零出局
- 手续费按名义价值双边收取；杠杆上限 100x（输入框和引擎都夹在这个范围）
- 爆仓价 = `入场价 × (1 ∓ 1/杠杆)`，用当根最低/最高价判定是否触发

### 展示
总收益率（对比买入持有）、最终权益、交易次数、胜率、最大回撤、盈亏比；
K 线图上标注买卖点（买/卖/空/平/爆）；权益曲线；逐笔成交明细。

> 权益守恒校验：`初始资金 + Σ每笔盈亏 = 最终权益`，误差 0（已验证）。
> 策略代码用 `new Function` 在本地执行——**只跑你自己写的代码**；若写了死循环会导致页面卡住。

### 回测区间
可选起止日期，或用快捷按钮（近 7 / 30 / 90 天、近 1 年）。
接口 `/api/klines` 支持 `startTime` / `endTime`，后端按 1000 根分页拉取，单次上限 5000 根（超出会标记 `truncated`）。
